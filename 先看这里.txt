订单工作台 v1.21.0 正式版 · 更新下载自动重试与归档

新增整单归档：
在“全部订单”的订单汇总行直接点击“归档整单”，确认后自动保存，包含该合同全部机型，不受当前搜索或阶段筛选影响。
在左侧“归档订单”点击“恢复整单”，一次恢复全部机型。详情页“订单资料”的入口同样改为整单操作。
归档会移出日常订单及优先待办；原流程、料号、依据和操作记录保留。持续追踪独立保留。
兼容旧版仅部分机型已归档的订单，可整单归档或整单恢复。

新增持续追踪归档：
已确认事项可点击“归档”，也可用“归档全部已确认”集中整理；操作后立即保存。
默认只显示未归档事项。筛选选择“已归档”可查看或恢复；“全部（含归档）”可跨状态搜索。
恢复后保留原确认状态和时间，归档、恢复均按账户留痕，完整备份保留相关状态和记录。
旧事项无需迁移，默认未归档。归档与订单归档互不影响。
新增 Cloudflare 主更新源与 GitHub 备用：
版本清单优先从 https://order-workbench-updates.nuoyanzhang99.workers.dev/latest.json 读取，无法使用时自动检查 GitHub。
下载失败或文件在一个来源暂缺时会尝试另一个来源。连接或传输中断继续沿用最多 15 次重试与最长两分钟等待；哈希、大小或磁盘错误仍立即停止。
新地址只允许指定 HTTPS 域名，下载后继续校验整个程序包、内部清单和各程序文件，不上传订单、账户、依据或任何本地数据。
下载页：https://order-workbench-updates.nuoyanzhang99.workers.dev/
GitHub 与 Cloudflare 均提供正式 v1.21.0。旧版程序需要升级一次到支持双源的版本后，才能自动使用新地址。
新增更新下载自动重试
下载遇到网络连接故障、超时、临时服务器错误或截断时，最多自动重试 15 次。前 7 次分别等待 5、10、20、30、45、60、90 秒，第 8 到 15 次每次等待 120 秒。
每次重试重新完整下载，界面显示重试次数与进度。等待和下载期间均可点击取消。
达到重试上限后显示失败原因，可点击“重新下载”手动重试。
文件不存在、磁盘写入错误、大小异常和哈希校验失败会直接报告原因。
手动更新请保存退出原程序后，将完整程序文件覆盖到原目录，保留 data 文件夹。

“优先待办”
从整单首次加入工作台起按连续 48 小时计算。到期仍有机型的机器料号为空，整单自动列入优先待办。
侧栏按订单计数，每单只列一行，显示简称、合同号、客户、加入时间和截止时间，可直接进入整单确认填写。
部分补齐仍保留，全部补齐自动移出；重新清空料号后按原加入时间再次判断。
归档订单排除。工作台打开时到期自动刷新，重新打开时根据原保存时间计算。
原订单无需迁移，沿用 createdAt，缺失时参考原生产单导入时间。

新增纸箱核对：图案 / 版面、与业务确认的箱型、尺寸分别记录。
少量优先考虑牛皮纸箱，数量多可考虑彩箱，按业务实际确认填写。
在“丝印与包材要求”填写，整单确认也可按所选机型批量操作。
需要纸箱时，图案 / 版面、箱型和尺寸确认后才能交计划。不需要纸箱时跳过这三项。
旧版已交计划的订单保留原交接状态，未单独记录的箱型和尺寸可补确认。

新增“持续追踪”：
1. 左侧选择“持续追踪”，点击“新增事项”，内容全部由你填写。
2. 可选关联整单，也可以作为独立事项，不需填写负责人、交期或流程阶段。
3. 勾选即确认并保存；取消勾选则恢复待确认。支持编辑、删除、搜索和状态筛选。
4. 订单完成、归档后事项仍保留，追踪操作不改变原订单流程。
5. 栏目“修改记录”集中查看账户、时间、变更内容；相关订单的修改记录也有入口可查。
6. 编辑未保存时，原有右上角关闭保存提醒及 Ctrl+S 继续适用。
7. 完整 JSON 备份包含追踪事项及记录。旧备份缺少追踪字段时，导入不会清空已有事项。

安装与更新：
使用正式版时，解压覆盖程序文件并保留原 data 文件夹。
先保存并退出原程序，将本包解压到原程序文件夹，覆盖程序文件，保留原 data 文件夹。
包中不含 data，不需要导出再导入原订单；原账户、订单、设置仍由原 data 读取。
如果在新文件夹独立使用，会使用新的空数据，不会自动读取另一目录的订单。

启动“订单工作台.exe”，保持 WebView2 DLL 与 runtimes 文件夹完整。
仍为本地版本，本次没有实施服务器或云端同步。
